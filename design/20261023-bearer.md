# `Bearer` challenges and credentials

Date: 2026-10-23

# Problem statement

OAuth 2.0 resource servers send `Bearer` challenges
([RFC 6750 section 3](https://datatracker.ietf.org/doc/html/rfc6750#section-3)),
optionally with `resource_metadata`
([RFC 9728 section 5.1](https://datatracker.ietf.org/doc/html/rfc9728#section-5.1)),
and read the token from `Authorization: Bearer <token>`
([RFC 6750 section 2.1](https://datatracker.ietf.org/doc/html/rfc6750#section-2.1)).
Clients read those challenges and send the token.

The RFC text is in [20261023-bearer-rfc.md](20261023-bearer-rfc.md).

Non-goals: the optional form-body and query methods (RFC 6750 sections 2.2,
2.3); token validation; fetching or validating metadata (RFC 9728 section
3.3); transport security (RFC 6750 section 5).

# Decision outcome

Module `bearer`. The client half has no feature gate and no dependencies; the
server half is behind `server`.

*   `bearer::Client`, from a `Bearer` `ChallengeRef`: `realm()`, `scope()`,
    `error()`, `error_description()`, `error_uri()`, `resource_metadata()`,
    and `respond(token)`.
*   `bearer::encode_credentials(token)`, like `basic::encode_credentials`.
*   `bearer::ChallengeBuilder`, `bearer::ErrorCode` (`status()` 400 / 401 /
    403) and `bearer::Credentials::parse`, behind `server`.

The client and server check challenge values with the same functions, so a
challenge the builder writes is one the client accepts, and the reverse.

## Validation rules

| Rule | Source | Builder | Client |
|---|---|---|---|
| At least one auth-param | 6750 §3 | `ConfigError` | `ClientError` |
| `realm`, `scope`, `error`, `error_description`, `error_uri` at most once | 6750 §3 | by construction | `ClientError` |
| `resource_metadata` at most once | 9728 §5.1 | by construction | `ClientError` |
| `realm` is a quoted-string | 6750 §3 | `ConfigError` | parser |
| `scope` = `scope-token *( SP scope-token )`, `scope-token = 1*NQCHAR` | 6749 A.4 | `ConfigError` | `ClientError` |
| `error` = `1*NQSCHAR` | 6749 A.7 | `ErrorCode` only | `ClientError` |
| `error_description` = `1*NQSCHAR` | 6749 A.8 | `ConfigError` | `ClientError` |
| `error_uri` is an absolute `URI` | 6750 §3, 6749 A.9, 3986 §3 | `ConfigError` | `ClientError` |
| `resource_metadata` is an `https` `URI` with a host and no fragment | 9728 §1.2, §3, §5.1 | `ConfigError` | `ClientError` |
| Token is a `b64token` | 6750 §2.1 | — | `ClientError` |
| Credentials are `"Bearer" 1*SP b64token` | 6750 §2.1 | `ServerError::Malformed` | — |

Unknown auth-params are ignored (RFC 6750 section 3).

## Caller duties

*   Send a `Bearer` challenge on every 401 for a protected resource (RFC 6750
    section 3).
*   Leave out `error` when the request had no credentials (RFC 6750 section
    3.1).
*   Respond with `ErrorCode::status()`.

# Testing

*   RFC 6750 section 3 and RFC 9728 section 5.1 examples, on both sides.
*   Builder output parsed back with `parse_challenges` and `Client`.
*   `respond` output parsed back with `Credentials::parse`.
*   One negative test per rule, on each side that checks it.
*   Fuzzing: `bearer_uri` compares the URI check with `iri-string`.
